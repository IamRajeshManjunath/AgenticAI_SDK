# Migration Guide: v0.2.x to v0.3.0

## Overview

Version 0.3.0 introduces major architectural changes for production readiness:
- JSON-only configuration (agenticai.json)
- Immutable workflow revisions
- Skills system with sandboxed execution
- OpenTelemetry GenAI semantic conventions
- Kubernetes-agnostic deployment

## Breaking Changes

### Configuration Format

**Before (v0.2.x):**
```yaml
# config.yaml
platform:
  name: agenticai
  environment: production
chat_models:
  primary:
    type: openai
    model: gpt-4o
```

**After (v0.3.0):**
```json
// agenticai.json
{
  "platform": {
    "name": "agenticai",
    "environment": "production",
    "version": "0.3.0"
  },
  "chat_models": {
    "primary": {
      "type": "chat_model",
      "provider": "openai",
      "model": "gpt-4o",
      "api_key_env": "OPENAI_API_KEY"
    }
  }
}
```

### Migration Steps

1. **Convert YAML to JSON:**
   ```bash
   # Using yq
   yq eval -o=json config.yaml > agenticai.json
   ```

2. **Update chat model configuration:**
   - Add `id` field (required)
   - Change `type` from `openai` to `chat_model`
   - Add `provider` field
   - Move `api_key` to `api_key_env` referencing environment variable

3. **Add required fields:**
   - `platform.version` (required)
   - `chat_models.*.id` (required)
   - `database_routes.*.name` (required)

### API Changes

#### Workflow Execution

**Before:**
```python
result = await client.run(workflow="my_workflow", input_data={...})
```

**After:**
```python
result = await client.run(workflow="my_workflow", input={...})
# 'input' parameter renamed from 'input_data'
```

#### Configuration Management

**Before:**
```python
config = load_config("config.yaml")
```

**After:**
```python
from agenticai_sdk.config import ConfigurationManager
manager = ConfigurationManager()
config = manager.load()  # Loads agenticai.json with env overrides
```

### Database Schema Changes

Run migrations:
```bash
alembic upgrade head
```

Key changes:
- `workflow_revisions` table for immutable revisions
- `audit_logs` table separate from `activity_logs`
- New indexes for performance

### Skills System

New in v0.3.0 - no migration needed, but you can now:
- Define skills in `skills/` directory with SKILL.md
- Create pipelines programmatically
- Execute with sandboxed isolation

### Deployment

#### Docker Compose (updated)
```bash
docker compose up -d  # Uses new Dockerfile with health checks
```

#### Kubernetes (new)
```bash
# Deploy to dev
kubectl apply -k deploy/kubernetes/overlays/dev

# Deploy to prod
kubectl apply -k deploy/kubernetes/overlays/prod
```

### Environment Variables

New required variables:
- `SECRET_KEY` - JWT signing key (use secrets manager in prod)
- `ENCRYPTION_KEY` - Data encryption key
- `AGENTICAI_DB_URL` - Database connection string

### Deprecated Features

- YAML config files (use agenticai.json)
- Direct database URL in code (use config manager)
- In-memory rate limiter for production (use Redis)

## Rollback Procedure

If issues arise:
1. Revert `agenticai.json` to previous version
2. Run `alembic downgrade -1` if DB migration applied
3. Restart services with previous Docker image
